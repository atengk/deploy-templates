# 坚持单应用交付边界，不捆绑有状态中间件

实际生产环境中，数据库、缓存与消息队列通常由云托管服务或独立基础设施集群运维，而不与应用进程同生命周期发布。我们决定所有部署模板严格遵循单应用交付（App-only Delivery）边界：仅负责应用自身的构建、运行与治理，外部有状态依赖统一通过环境变量注入，不在模板中捆绑 MySQL、Redis 等中间件容器。

## 备选方案（Considered Options）

- **全栈一体编排（应用 + MySQL + Redis + Nginx）**：本地演示开箱即用，但极易误导使用者将有状态存储与应用耦合发布到生产，且会大幅增加维护与安全更新负担。

## 影响（Consequences）

- 模板专注应用本身的工程最佳实践，结构清晰、迁移成本低；若未来需要中间件部署参考，将独立于应用模板之外另行组织。
